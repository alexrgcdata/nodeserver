# Using the API

## Local configuration

Run `npm run setup` once. It creates `config.local.json` beside `package.json`
with a cryptographically random 256-bit token. Existing files are never replaced.
Keep this file private and outside any public web directory. It is ignored by
Git. Unix creation permissions are 0600; Windows access follows folder permissions.

| Setting | Default | Accepted values |
| --- | --- | --- |
| `host` | `127.0.0.1` | A nonempty hostname or IP address |
| `port` | `8080` | Integer 0-65535; 0 asks for an available port |
| `maxRequestBytes` | `65536` | Integer 1-1048576 |
| `token` | Generated by setup | 43-128 base64url characters |

Keep the loopback host for local use. Startup prints the actual listening port.
The server reads configuration at startup; restart after changing it. Replacing
the token and restarting invalidates the old token. There are no issued sessions,
token expiry, roles, registration, password storage, or login endpoints.

`npm run demo` uses the private token without printing it. It starts a temporary
loopback listener on a free port, verifies each action and a 401 response, then
closes the listener. It doesn't require `npm start` in another terminal.

To make your own call in PowerShell, from the project root:

```powershell
$config = Get-Content ./config.local.json -Raw | ConvertFrom-Json
$headers = @{ Authorization = "Bearer $($config.token)" }
$body = @{ action = 'echo'; params = @('hello', 42, $true) } | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:$($config.port)/api" `
  -Method Post -Headers $headers -ContentType 'application/json' -Body $body
```

This example assumes the default loopback host and a nonzero port. Don't print
`$config` or `$headers`, since they contain the private token.

## HTTP contract

`GET /health` is public and returns `"ok"` as its result.
`POST /api` requires exactly one `Authorization: Bearer ...` header and
`Content-Type: application/json`, optionally with `charset=utf-8`. Authentication
runs before method checks, body parsing, or action dispatch on `/api`.
Bodies must be uncompressed UTF-8 JSON. CORS is not enabled; use a server-side
client, a terminal, or the bundled demo.

```json
{
  "action": "echo",
  "params": ["hello", 42, true, null, { "nested": [1, 2] }],
  "time": "2026-10-30T12:00:00Z"
}
```

- `action` is a case-sensitive registered name of 1-64 characters.
- `params` is required and must be an array. Use `[]` for no arguments.
- `time` is optional client metadata. When supplied, it must be an RFC3339
  timestamp with a timezone. Empty strings, null, impossible dates, and leap
  seconds are rejected. It isn't used to authenticate a request.

Unknown envelope fields and multiple JSON values are rejected.

| Action | Parameters | Result |
| --- | --- | --- |
| `hello` | `[]` | `"hello world"` |
| `success` | `[]` | `"successful"` |
| `boolean` | `[]` | `true` |
| `echo` | Any JSON array | The same array |

Strings, booleans, null, arrays, and objects retain their JSON types. JavaScript
uses double-precision numbers. Send large integer identifiers as strings when
exact values beyond `Number.MAX_SAFE_INTEGER` matter; this differs from the Go
version's raw JSON echo. Numeric overflow such as `1e400`, including nested
values, receives HTTP 400 rather than silently becoming null.

The four action names and response fields match the Go dispatcher, but the
implementations aren't byte-for-byte interchangeable. Node generates UUID
request IDs and millisecond timestamps, uses its own config field names and
token format, and validates UTF-8 and timestamps more strictly. For example,
Node rejects an explicitly empty or null `time`; Go currently treats those as
omitted. Error codes for some malformed envelopes can differ. For shared
clients, omit `time` when unused and rely on the documented fields and statuses.

## Responses and errors

```json
{
  "success": true,
  "result": true,
  "error": null,
  "request_id": "dc2c8527-55e7-4af4-8c3a-d71dd2b67598",
  "time": "2026-10-30T17:00:00.000Z"
}
```

Every application response has these fields. `X-Request-ID` matches `request_id`;
`time` is generated by the server in UTC. Responses use `Cache-Control: no-store`
and `X-Content-Type-Options: nosniff`. Errors set `success` to false, `result` to
null, and `error` to an object with a stable `code` and a safe `message`.

| Status | Meaning |
| --- | --- |
| 400 | Invalid JSON, envelope, timestamp, or action parameters |
| 401 | Missing, malformed, duplicate, or incorrect bearer token |
| 404 | Unknown HTTP route or action |
| 405 | Wrong method; `Allow` names the accepted method |
| 408 | Request body deadline exceeded |
| 413 | Body exceeds the configured byte limit |
| 415 | Unsupported content type, charset, or compression |
| 500 | Unexpected failure; internal details stay private |

Malformed HTTP and header timeouts may get Node's own HTTP errors rather than
the application envelope. The token is compared through fixed-size SHA-256
hashes using a timing-safe comparison. Request bodies, tokens, and internal
exceptions are not logged.

## Timeouts and extension points

Body reads have a ten-second total deadline; sockets have a fifteen-second
inactivity timeout and keep-alive lasts five seconds. Unauthorized and oversized
requests close the connection when their bodies are unread. Shutdown allows up
to five seconds for active requests before closing remaining connections.

Add functions in `src/functions.js`, register them in `src/actions.js`, and add
HTTP tests in `test/server.test.js`. Throw `ParamsError` only for messages safe
to show callers. Unexpected exceptions produce a generic 500 response.

Future asynchronous actions need cancellation and their own upstream deadlines.
HTTP timers cannot interrupt CPU-bound JavaScript. Public deployment would also
need a Node-capable host, HTTPS, and an access/rate-limiting policy. No hosting or
external integration is configured by this project.
